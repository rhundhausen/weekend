# Map View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the "Map view is coming soon" note with a working map of the filtered events, placed by source address, then a venue lookup, then town center.

**Architecture:** Adapters attach an optional `location` to raw events. Refine turns those, plus Nominatim lookups for the rest, into a per-city cache `data/venue-locations.json` keyed by `venueKey`, and strips `location` from the stored events. The Hugo build gives each browser event an `l: [lat, lon, exact]` from that cache or from `city.json`'s new `cityCenters`. A new `map.js`, loaded only when Map is first chosen, draws them with a vendored MapLibre GL JS on OpenFreeMap tiles.

**Tech Stack:** PowerShell 7.4 and Pester 6 (ingestion), Hugo templates, plain ES2020 bundled by Hugo `js.Build`, MapLibre GL JS (CSP build), OpenFreeMap vector tiles, Nominatim search API.

**Spec:** `docs/superpowers/specs/2026-11-23-map-design.md`

## Global Constraints

- No en-dashes or em-dashes anywhere: code, comments, docs, copy, commit messages.
- Commit messages: one-line subject, then the Co-Authored-By and Claude-Session trailers. No PII, secrets, or secret names. Confirm each commit with the owner. One change per commit.
- Work on a local branch `map` in `weekend`. Nothing is pushed until Task 9: every push to `weekend` main rebuilds both live sites.
- JSON files written by refine: 2-space, LF, final newline, keys sorted (same as `Write-WkCityLookupState`).
- Nominatim: at most 1 request per second, the project User-Agent (`Get-WkUserAgent`, sent by `Invoke-WkRequest`), every answer cached. Tests never call it: pass a `-Fetch` scriptblock, as `Invoke-WkCityLookup` does.
- The visitor's coordinates are never sent, stored, logged, or put in a URL.
- MapLibre's code and CSS load only on the first Map click. The list page's first load must not grow beyond the few bytes of `l` per event.
- Content-Security-Policy keeps `script-src 'self'` and `style-src 'self'`. Additions are only the ones in Task 7.
- "The box": a point is near the city when it is within 150 miles (great-circle) of `city.json` `coordinates`. Used for feed coordinates, lookup results, and the visitor's position.
- Placeholder venue: `venueKey` starts `various-` or ends `-area`, or its events in `events.json` fall in more than one town (`city`, ignoring `Other`).
- Run the full Pester suite before each commit: `Invoke-Pester ingestion/tests` from `weekend`, with `weekendboise` checked out beside it. Currently 853 pass.

## Review Focus

1. A venue whose feed coordinates disagree between sources (two Ticketmaster records, slightly different points): the most often reported pair wins, ties go to the source with the best priority. Test in Task 3.
2. A Nominatim answer that is a different place with the same name in another state or across the metro: anything outside the box is rejected and stored as `none`. Test in Task 3.
3. A filter change while the map is open, including one that leaves zero events: the map redraws, shows "0 events", and does not throw. Check in Task 7's browser pass.
4. Location denied, timed out, or unsupported (http, old browser), and a position outside the box: all fit the shown events, with no dot. Check in Task 7's browser pass.
5. A `manual` entry for a venue that also has feed data: never changed. Test in Task 3.

### Task 3: The venue location cache

**Files:**
- Create: `ingestion/scripts/lib/VenueLocations.ps1`
- Create: `ingestion/schema/venue-locations.schema.json`
- Modify: `ingestion/scripts/Test-Schema.ps1` (validate `data/venue-locations.json` when it exists)
- Test: `ingestion/tests/lib/VenueLocations.Tests.ps1`

**Interfaces:**
- Consumes: `Test-WkNearCity`, `Invoke-WkRequest`, `Get-WkCity`.
- Produces:
  - `Read-WkVenueLocationState -Path <string>` returns `[hashtable]` venueKey to `[ordered]` entry; a missing file gives `@{}`.
  - `Write-WkVenueLocationState -Path <string> -State <hashtable>` writes sorted, LF.
  - `Get-WkPlaceholderVenues -Events <object[]>` returns `[string[]]` venueKeys (the Global Constraints rule).
  - `Update-WkVenueLocations -RawEvents <object[]> -Events <object[]> -State <hashtable> -Now <DateTimeOffset> [-MaxLookups 300] [-Fetch <scriptblock>]` returns `@{ State; Looked; Found; Feed }` (counts for the run log).
- Entry shape: `lat`, `lon` (numbers, when known), `address` (when known), `from` (`feed`|`lookup`|`zip`|`manual`|`none`|`placeholder`), `checked` (`YYYY-MM-DD`). Schema requires `from` and `checked`, requires `lat` and `lon` for `feed`, `lookup`, `zip`, `manual`.

`Update-WkVenueLocations` rules, in order, for each distinct `venueKey` in `-Events`:
1. `manual`: never touched.
2. Placeholder (`Get-WkPlaceholderVenues`): set `from: placeholder`, no point.
3. Feed: if any raw event with this `venueKey` has `location.lat/lon`, use the pair reported by the most raw events (ties: first in raw order); store with `address` from the same event, `from: feed`. Replaces `lookup`, `zip`, `none`, `placeholder`.
4. Otherwise, when there is no entry, or a `none` entry with `checked` at least 30 days before `-Now`, and fewer than `-MaxLookups` lookups so far: query `https://nominatim.openstreetmap.org/search?format=jsonv2&limit=1&countrycodes=us&bounded=1&viewbox=<box>&q=<text>` where text is the feed `address` when one exists, else "venue, town, state name". Accept a result only when `Test-WkNearCity`. Store `from: lookup`. If no result and a feed address has a 5-digit ZIP, query `...&postalcode=<zip>&country=us` (no `q`) and store `from: zip`. Otherwise `from: none`. Sleep so requests are at least 1 second apart. A thrown error warns and leaves the entry unchanged.
5. Entries for venues no longer in `-Events` are kept (venues come back).
