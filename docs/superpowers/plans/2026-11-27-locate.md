# Locate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A weekly `locate` workflow finds venue street addresses on events' own pages (or in feeds), turns them into points with the Census geocoder, and refine stops making any lookup requests.

**Architecture:** Refine's `Update-WkVenueLocations` keeps only network-free work (feed points, placeholders). A new lib `VenueAddress.ps1` reads addresses from page HTML and geocodes them; `Invoke-Locate.ps1` drives it over the venue queue and writes `data/venue-locations.json`. A reusable core workflow `locate.yml` runs it; each city repo has a trigger file.

**Tech Stack:** PowerShell 7.4, Pester 6, GitHub Actions, US Census geocoder, Nominatim structured search.

**Spec:** docs/superpowers/specs/2026-11-27-locate-design.md

## Global Constraints

- No name searches anywhere; no AI calls; no Google.
- Robots.txt checked per host (`Test-WkRobotsAllowed`), bot User-Agent (`Invoke-WkRequest`), at least 1 second between requests to one host.
- `manual` entries never change. A feed point beats `page` and `address`.
- `from` values: feed, page, address, lookup (legacy, never written anew), zip, manual, none, placeholder.
- Every point passes `Test-WkNearCity` (150 miles).
- No en-dashes or em-dashes in any text. Commit subjects one line plus the session trailers.

## Review Focus

- A listing page (many JSON-LD events) must give the address of the event whose title matches, never the first one.
- A footer address (organizer's office) with no venue name before it must be ignored.
- A Census outage must fall through to Nominatim and ZIP, not end the run.
- A recheck that finds nothing must keep the old pin.
- Refine must make zero HTTP requests for venues.

### Task 3: Turn an address into a point

**Files:**
- Modify: `ingestion/scripts/lib/VenueAddress.ps1`
- Test: `ingestion/tests/lib/VenueAddress.Tests.ps1`

**Interfaces:**
- Produces: `Find-WkAddressPoint -Address <string> -Fetch <scriptblock> -Health <hashtable>` -> `@{ lat; lon; from = 'address'|'zip' }` or `$null`. Order: Census `https://geocoding.geo.census.gov/geocoder/locations/onelineaddress?address=...&benchmark=Public_AR_Current&format=json` (`result.addressMatches[0].coordinates.y/x`), then Nominatim `search?format=jsonv2&limit=1&countrycodes=us&street=&city=&state=&postalcode=` (rejecting area addresstypes), then Nominatim `postalcode=` (from = zip). `$Health[service]` counts failures in a row; at 3 the service is skipped. A 404 or empty answer is not a failure.
- [ ] Tests: Census hit; Census miss -> Nominatim structured; both miss -> zip; Census throwing 3 times -> skipped afterwards, Nominatim still asked; far-away point rejected; no street (just a ZIP) -> zip only.
- [ ] Fail, implement, pass, full suite, commit "Turn venue addresses into points with the Census geocoder".
